# 开发迭代评估

## 迭代一：仓库内路径安全与报告写入保护

- 本轮修改：新增 `repo_paths.py`，统一解析仓库内文件和图片；Markdown 扫描、AI 图片读取、Anki 媒体读取接入安全入口。报告写入改为临时文件、`flush/fsync`、`os.replace`，周测和复盘题目/答案使用同一运行锁成对写入。
- 验收标准：拒绝远程 URL、Windows 绝对路径、仓库外逃逸和仓库外符号链接；图片读取检查常见文件头；已有 CLI 与来源解析测试保持通过；无外部 AI 调用。
- 实际证据：`python -m unittest discover -s 自动化\\tests -v` 运行 35 项，全部通过；`python -m compileall -q 自动化 Anki\\build_anki.py` 通过；`python 自动化\\main.py check --date 2026-07-31` 返回数学 8 个、408 10 个来源且无问题。
- 结果：通过。
- 遗留风险：Question ID、Git tracked ref、统一流水线状态元数据和 CI 尚未接入；Anki 全量构建尚未在本轮执行。

## 迭代二：Question ID、tracked_ref 与统一运行状态

- 本轮修改：配置 subjects 改为列表并保留旧映射兼容；Git 只读取 `git.tracked_ref` 祖先链，兼容解析无空格的 `daily:YYYY-MM-DD` 并跳过 merge commit 误报；新增 `索引/题目索引.json`、`index --dry-run`/`index`、图片 SHA-256、路径别名和统一 Question ID，并接入来源索引、复盘目标、Anki GUID/清单；日报、周测、复盘、纠错报告新增统一流水线元数据和状态。
- 验收标准：稳定 ID 不依赖行号；dry-run 不调用真实 AI；四类 CLI 在 `--no-ai --dry-run` 下可运行；失败/无 AI 明确为 `needs_review` 或 `rejected`；CI 可在无 API 凭据环境运行。
- 实际证据：现有单元测试 40 项全部通过；`compileall` 通过；日报、周测、复盘、纠错的 no-AI dry-run 均返回 0 并输出 `status: needs_review`；`index --dry-run` 输出 schema、图片 SHA-256 和路径别名，实际索引写入后发现并保留了仓库中的孤立题图问题；新增 `.github/workflows/ci.yml` 和安全/最小写入测试。
- 结果：通过，但发现项需要后续人工整理；不能将当前索引/报告标为 validated。
- 遗留风险：本轮新增安全专项测试和 CI 尚未在最后一次全量测试中执行；Anki 需要其独立依赖环境，尚未构建成品包；现有历史 Markdown 中的绝对题图引用现在会报告为待确认，不自动迁移。

## 迭代三：共享验证门禁、CI 与文档边界

- 本轮修改：新增四类工作流共用的来源 ID 验证和状态判定模块；未知来源编号升级为 `rejected`，无 AI 或有结构/来源问题保持 `needs_review`；Anki 笔记和题图扫描改读 subjects 配置；新增安全、伪装图片、稳定 ID、报告成对写入测试和 GitHub Actions CI；修复 README 的绝对路径与模型说明冲突，明确 `.apkg` 不默认纳入 Git。
- 验收标准：所有本地测试与编译通过；日报、周测、复盘、纠错 no-AI dry-run 不调用真实 API 且返回 0；索引命令发现问题时返回非零并仍输出明确问题；不修改原始题图和已有笔记。
- 实际证据：`python -m unittest discover -s 自动化\\tests -v` 共 40 项全部通过；`python -m compileall -q 自动化 Anki\\build_anki.py` 通过；四个 no-AI dry-run 均返回 0；`index` 返回 2，报告仓库现有孤立题图/绝对路径问题；`git diff --check` 无空白错误。
- 结果：通过。当前 worktree 的安全、Question ID、统一验证状态和 CI/本地验收闭环已形成；发现项仍按待人工确认处理。
- 遗留风险：未在本轮运行 Anki 成品构建（依赖安装/运行成本较高）；未对历史绝对引用做自动迁移；CI 尚未在远端实际执行；Anki 的完整两科卡组复核仍需独立依赖环境验收。

- 实际证据：`python 自动化\\main.py index` 返回 2；随后对 `索引/题目索引.json` 执行外部路径模式扫描，输出“索引无外部别名”。

- 遗留风险：历史 Markdown 中的绝对引用仍需用户确认后逐条改为仓库内相对引用，程序不会自动迁移。

- 验收标准：audit 不改题图/Markdown；真实历史问题保留为 findings；机器可读元数据字段齐全且状态与 pipeline_validation 一致；Anki 外部/绝对/逃逸媒体引用被拒绝，fixture 失败返回非零。
- 实际证据：自动化测试 43 项全部通过；`compileall` 通过；日报、周测、复盘、纠错 no-AI dry-run 均返回 0；Anki fixture 返回 `{"status":"validated","external_media":"rejected"}`；真实 `audit` 写出 `报告/审计/仓库审计-2026-08-01.json` 与 `.md`，JSON 可由 PowerShell `ConvertFrom-Json` 读取，status 为 `rejected`、findings 47 条；`index` 返回 2，保留历史索引问题。

## 迭代八：审计索引空哈希误报修正

- 本轮修改：主线程复核真实 audit 报告时发现，缺少题图的索引记录会把 JSON 中的 `null` 图片哈希转成相同字符串，从而误报 `index.duplicate_image_identity`；修正为仅对非空图片哈希执行重复身份比较，并增加最小 fixture 回归测试。
- 验收标准：两个没有图片哈希的 Question ID 可以并存并分别作为待补/孤立索引问题；不生成重复图片身份的虚假 finding；非空哈希冲突检测保持不变。
- 实际证据：新增安全回归测试后，`python -m unittest discover -s 自动化\\tests -v` 共 44 项全部通过；`python -m compileall -q 自动化 Anki\\build_anki.py Anki\\check_anki.py`、`python Anki\\check_anki.py` 和 `git diff --check` 均通过。重新运行真实 `audit` 后，JSON 使用 UTF-8 的 Python 与 PowerShell `ConvertFrom-Json` 均可解析，status 为 `rejected`、findings 为 34 条；`index.duplicate_image_identity` 中没有空哈希误报。
- 结果：通过。真实仓库仍因历史断链、绝对路径、孤立题图、过渡站积压和未验证报告保持 `rejected`，但审计规则不再把缺少图片哈希的记录误判为重复图片身份。
- 遗留风险：真实仓库仍有历史索引 orphan、断链、绝对路径、孤立题图和未验证报告；本轮只修正审计误报，不改变索引、题图或笔记。

## 迭代十：合并前语义与跨平台门禁

- 本轮修改：将验证状态改为显式门禁，`validated` 必须通过结构、来源、领域独立核验以及适用的题答配对和答案泄漏检查；日报/周测写入实际来源提交范围，复盘/纠错写入 snapshot commit；生产 ref 默认改为 `refs/heads/main`，CLI 支持 `--tracked-ref` 并在启动时校验 ref。
- 本轮同时将 Question ID 改为索引首次写入时生成并持久保存的随机 ID，图片 SHA-256、路径别名和语义指纹只作为匹配元数据；未登记、多候选、重复哈希进入待确认；Anki 增加独立 `题目ID` 字段和 `qid::...` 标签，科目与复习参数改为配置驱动。
- 写模式工作流从收集阶段起持有带 pid/主机/启动时间/run_id 的锁，支持陈旧锁接管；题目/答案双文件使用双临时文件和失败恢复；图片读取增加 Pillow 真实格式校验、大小和像素上限；审计区分源 Markdown 与报告/文档，按标题节边界检查无来源题目，并校验成对报告 run_id。
- CI 增加周测、复盘、纠错 no-AI 验收和 Windows job；移除 Git 对历史 `.apkg` 二进制的追踪但保留工作区文件；路径构造统一使用 POSIX 分段，避免在 Linux runner 中拼接 Windows 反斜杠。
- 验收标准：本地单元测试、`compileall`、Anki 安全 fixture、四个 no-AI dry-run、`git diff --check` 全部通过；真实历史资料仍只产生 findings，不自动修改题图、Markdown、索引或报告。
- 实际证据：`python -m unittest discover -s 自动化/tests -v` 共 52 项全部通过；`python -m compileall -q 自动化 Anki` 通过；`python Anki/check_anki.py` 返回 `validated`；完整 `python Anki/build_anki.py` 返回 408 为 41 张、数学为 36 张、媒体 78 个，重新导入验证 77 张笔记/77 张卡片/78 个媒体引用；daily/weekly/review/correct no-AI dry-run 均返回 0；新增审计分层与题目节边界 fixture 通过；真实仓库的 `index`/`audit` 仍按已有资料问题返回非零。
- 结果：本地实现达到合并前可审阅状态；仍需在远程分支确认 Ubuntu/Windows CI 实际运行结果后，才能重新评估是否具备合并条件。
- 遗留风险：历史绝对路径、孤立题图、旧版索引记录和未验证报告仍需人工确认；本分支不自动合并，也不替用户改写源资料。
